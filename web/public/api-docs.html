API REFERENCE · v1

Verify identities from your own systems.

The TruvoID API lets your servers check a Nigerian NIN, BVN or phone number and get a clear answer in one request. Every workspace starts in free test mode; live checks unlock once TruvoID approves your organization profile.

Base URL https://api.gettruvoid.com  ·  JSON over HTTPS  ·  amounts in kobo (₦1 = 100 kobo)

Quick start

  1. Create a workspace (free, no card needed).
  2. In the dashboard, open API keys and generate a TEST key. It starts with trv_test_ and is shown once — store it as a secret.
  3. Make your first call with a test number:
curl https://api.gettruvoid.com/v1/verify/nin \
  -H "X-API-Key: $TRUVOID_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042" \
  -d '{"number": "00000000001"}'

You'll get back a match with a sample identity. Test calls are free and never touch real identity records.

Authentication

Authenticate server-to-server requests with your API key in the X-API-Key header. Never put a key in a browser or mobile app — anyone can read it there.

Key prefixModeWhat it does
trv_test_…TESTFree. Answers from test data only. Available immediately.
trv_live_…LIVEReal lookups, charged to your wallet. Available once your profile is approved.

The key decides the mode — you never pass a mode flag. Revoke a key from the dashboard at any time; it stops working immediately. A missing, unknown or revoked key returns 401.

Test mode

Test keys (and the dashboard's Test switch) run against a sandbox that behaves like the real service but returns fixed data. Use these numbers to exercise every outcome your integration must handle:

TypeMatchNo matchProvider error
NIN000000000010000000000200000000003
BVN222222222212222222222222222222223
Phone080000000010800000000208000000003

Any other well-formed number returns no_match in test mode, so a real NIN pasted into test mode never appears to verify. Test responses carry "environment": "sandbox" and "amountKobo": 0.

Going live

1 · Complete your profile

In the dashboard, fill in Organization setup, upload your supporting documents and submit.

2 · TruvoID review

We review your submission. If anything needs changing you'll see a note on your setup page; update and resubmit.

3 · Live keys

Once approved, generate a trv_live_ key, fund your wallet and switch your production config to it.

Until approval, live requests and live-key creation return 403 with code live_not_enabled. Test mode keeps working throughout.

The response

A completed request returns 200 — whether a record matched, didn't match, or the upstream provider failed (refunded). Always read status to decide what to do.

Idempotency

Networks fail. Send a unique Idempotency-Key per logical check (an order or customer ID works well). If you retry with the same key, TruvoID returns the original answer with "replayed": true and does not charge again. Keys are scoped to your API key. Sending the same key while the first request is still in flight returns 409 idempotency_conflict.

Replayed answers include the identity fields kept in your history, but not the photo or residential address — those are returned only once (see Data handling).

Billing & refunds

  • Live checks are prepaid from your wallet at your organization's price per type. Top up in the dashboard under Wallet.
  • The charge and the call record are written together: you're never charged without a record, or recorded without a charge.
  • provider_error is refunded automatically. If a call is ever left incomplete (for example, a network failure on our side), it is refunded automatically within minutes.
  • With too little balance you get 402 insufficient_balance and nothing is attempted.
  • Test-mode checks are always free.

Errors

Errors return a JSON body with a human-readable error and, where useful, a stable machine-readable code. Branch on code, not on the message text.

{ "error": "Your wallet balance is too low for this verification. Fund your wallet and try again.", "code": "insufficient_balance", "balanceKobo": 2000 }
HTTPcodeWhat to do
400invalid_requestFix the input (e.g. a NIN must be 11 digits). Nothing was charged.

Rate limits

Each API key can make up to 120 verification requests per minute (bursts allowed up to that limit). Beyond it you receive 429 with a Retry-After header. Need more? Contact us with your expected volume.

Data handling

  • The number you verify is stored only as a one-way hash — your history shows a reference, never the NIN, BVN or phone number itself.
  • The photo and residential address are returned to you once, in the live response, and are not stored by TruvoID. Store them yourself only if you have a lawful basis to.
  • Name, date of birth, gender, phone and state of origin are kept in your verification history for reconciliation.
  • Use the data only for the purpose you collected consent for, in line with the Nigeria Data Protection Act (NDPA). TruvoID is an independent verification provider and is not NIMC or any government body.

Agencies & outlets

Agencies can issue keys per outlet. A request made with an outlet key is recorded against that outlet and, for agency outlets, charged to the outlet's own wallet (which the agency funds). Institution outlets share the institution's wallet. The API is identical either way — only the key differs.

Code samples

// Node 18+ (built-in fetch)
const res = await fetch('https://api.gettruvoid.com/v1/verify/nin', {
  method: 'POST',
  headers: {
    'X-API-Key': process.env.TRUVOID_API_KEY,
    'Content-Type': 'application/json',
    'Idempotency-Key': `customer-${customerId}`,
  },
  body: JSON.stringify({ number: nin }),
})
const result = await res.json()
if (result.status === 'match') {
  console.log('Verified:', result.identity.fullName)
} else if (result.status === 'no_match') {
  console.log('No matching record')
} else if (result.status === 'provider_error') {
  console.log('Provider unavailable - not charged, retry later')
} else {
  console.error(result.code ?? result.status, result.error ?? result.message)
}
